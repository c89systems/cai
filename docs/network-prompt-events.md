# Network prompts and workspace events

This is the implementation specification. These options and tools are not yet shipped.

## Ownership

The Softline frontend owns its TCP prompt listener and all agent-requested outbound TCP prompt connections. The workspace backend owns multicast publication, multicast reception tools, and endpoint registration in the existing history store. A frontend never opens another Pouch client. It announces capabilities and endpoints through its existing authenticated workspace CBOR connection.

Use the standard CAI terms **workspace**, **session** and **attachment**. Network metadata and tools identify a live attachment by `attachment_id` and `server_instance`, and a saved session by `session_id`. [CAI terminology](README.md#terminology).

Reusable bounded socket, address, UTF-8 and event-writing code belongs in libcai. Tool declarations and host callbacks must also be usable by runtime embedders. Application configuration, Pouch registration, terminal editing and the concrete frontend action adapter belong in libcai_app. Core libcai acquires no storage, terminal or renderer dependency.

## TCP prompts

`--prompt-listener ADDRESS` enables one listener for the frontend. An empty address disables it. Accept `PORT`, `:PORT`, `HOST:PORT`, and bracketed IPv6 addresses. `--proto tcpv4|tcpv6` selects the family; the default is `tcpv4`. Omitted hosts mean `127.0.0.1` or `::1`, never a wildcard. Resolve hostnames once when opening the listener. IPv6 listeners are IPv6-only.

One accepted TCP connection carries one UTF-8 prompt. Ordinary EOF ends the prompt, including a peer shutting down its sending direction; no framing, request header or client implementation is required. Newlines are text, not Enter key events. Empty connections submit nothing. A reset, read error, malformed/incomplete UTF-8, embedded NUL, or exceeding the existing prompt-size limit rejects the prompt rather than submitting a prefix. While receiving or playing out one prompt, accept and immediately reject additional connections rather than leaving them as future prompts in the listen backlog. Release that slot after the complete prompt has been handed to Softline for submission/queueing, or rejected. Extract the existing strict incremental UTF-8 validation from libcai's CBOR handling for reuse rather than depending on Softline internals or adding a second incompatible decoder; keep its existing ASCII fast path.

Choose the input path when accepting the connection. When the editor has an empty ordinary draft, insert received complete UTF-8 characters using `sl_insert()` on the editor-owner thread, then call `sl_submit()` once after normal EOF and any paced insertion have finished. The resulting text is an ordinary editable Softline draft. Until receipt finishes, Enter does not submit a partial prompt; Escape cancels receipt and clears this incoming draft. On a detected receive/validation error, clear the partial incoming draft and pending insertion bytes, report the failure, and do not submit. This is simple draft cleanup, not a separate editor transaction or remote editing protocol.

When a local draft or queued-item edit already exists, leave it untouched. Receive the remote prompt separately within the existing prompt-size limit, and offer it to Softline's native turn queue only after normal EOF validates the complete input. Error or cancellation discards that pending input. No partial remote queue entry is ever created. Neither path steers or submits directly to the model; queue admission, editing, cancellation and receipts use the existing Softline backend policy.

The listener belongs to an attachment and stays with its backend. A TCP prompt targets the backend's active session when receipt begins. Discard unfinished input if the active session changes during receipt. Replies arriving after a session switch go to the newly active session. A parked attachment receives complete prompts through its own backend's turn queue.

`--simulate-typing [MS]` belongs only to the listener. Omission disables pacing; a bare flag selects 30 ms. Pace complete Unicode scalar values using the frontend's readiness/deadline mechanism, not sleeps in its event callback. EOF submits only after pending characters have been inserted. Retain bounded pending bytes and apply socket backpressure. Do not buffer an unbounded socket stream while typing slowly. Timers must not wake an idle frontend when no input is pending.

`--feed-tcp ADDRESS` is an executable-only stdin-to-TCP utility. Process it before normal CAI configuration, banner, workspace discovery, authentication, storage or agent startup. It understands the explicit address/family flags and ordinary `LOG_*` logging setup. It forwards arbitrary stdin bytes unchanged, handles short writes, and closes normally after successful transfer and stdin EOF. A detected stdin/transfer error aborts the connection rather than deliberately sending normal EOF for an incomplete prompt. It has no Unicode parsing or simulated typing. Its libpslog JSON records describe connection, transfer and failure; successful local transmission does not claim application-level delivery or inference completion. nc and socat are equally valid senders.

## Multicast publication

Multicast publication is disabled by default. `--event-multicast` selects automatic allocation; an explicit `GROUP:PORT` selects a fixed destination. Configuration uses an empty string for disabled and `auto` for automatic allocation. An ordinary frontend invocation can supply these settings when starting a new owner, but attaching to an existing owner must not silently reconfigure its publisher.

The configurable CAI default pool is `239.193.89.1` through `239.193.89.254`, with destination port `49189`. These are application conventions inside organization-local multicast space, not globally assigned CAI addresses. The organization-local block is defined by [RFC 2365](https://www.rfc-editor.org/rfc/rfc2365.html). Allocate the first free group using an atomic store lease, not a count of existing records or a check-then-write. Concurrent publishers sharing the registry cannot claim the same automatic slot. Other applications or independently configured stores can still choose the same destination. Explicit destinations do not silently increment. Exhaustion is an actionable startup error. Permit overriding the pool and port.

The sender uses nonblocking datagram writes with a bounded payload. The payload is journal-style event JSONL, preserving the stored event fields and semantics. A JSON line may cross several datagrams; do not add packet wrappers, extra newlines, full-event buffers or spools. This is deliberately loose, best-effort observation: loss, duplication or reordering can invalidate a line, and loss need not be detectable. Receivers joining mid-event can discard the partial line and resume at the next line boundary. They do not require an identity handshake or baseline before observing subsequent events. This is not a remote operating, journal replication, or recovery protocol. Internal commit/state records are not presentation events and are not published as session output.

Use the existing event serialization and live publication path, without rereading or rematerializing the session. Registration and attachment metadata identify the publishing workspace and its current session; the UDP stream does not guarantee identity discovery for late joins. Publication must continue with no frontend attached and must never block inference or durable journal writes. Network errors update counters and produce bounded diagnostics; do not recursively multicast publisher diagnostics.

Configuration uses socat-related names: `ip_multicast_if`, `ip_multicast_ttl` (default 1), and `disable_multicast_loop` (default false). Infer the multicast family from the destination independently of the TCP `proto` setting. Validate multicast destinations and explicit interface selection. A wildcard TCP bind address is not an advertised reply address.

Receivers must isolate the selected destination group even when several CAI streams share a UDP port. Native reception binds to the selected multicast group and applies the platform's group-delivery restriction where available, such as `IP_MULTICAST_ALL=0` on Linux. Generated socat commands also bind to the selected group rather than a wildcard. Verify two simultaneous groups on the same port remain separate.

## Discovery and attachment metadata

Register enabled TCP listeners and multicast publishers under the application namespace prefix, normally `cai.network`, using the backend's existing history client. Each record identifies endpoint kind and ID, protocol, bind and usable advertised addresses, host identity, workspace path/name, server instance, attachment where applicable, current session as descriptive metadata, and applicable socat instructions. Do not publish credentials. An optional advertised TCP address handles wildcard binds and externally reachable names; loopback addresses remain explicitly host-local.

The process holding the capability owns its registration through the backend. Publish only after successful socket setup; withdraw on normal listener/frontend/server close. Registration lifetime and automatic allocation claims must be crash-safe and use retained leases, not per-event acquisition. Stale records are discovery hints, never proof of a live endpoint. Prevent an old owner from deleting a successor's record. Session switches update attribution without opening a second store or registering a second listener.

`cai -l` and `cai -L` include registered endpoints with their workspace and session listings, observing existing local/all scope. Headless startup logs the actual publication destination, interface and ready-to-use socat command. Every attaching frontend receives typed current network metadata over CBOR, including an already-running owner's actual allocation. Render that metadata as a startup notice; do not parse log messages or synthesize user prompts to communicate it.

Example receive command, with its interface selected from the actual configuration:

```sh
socat -u 'UDP4-RECV:49189,bind=239.193.89.1,reuseaddr,ip-add-membership=239.193.89.1:127.0.0.1' STDOUT
```

## Agent tools and frontend actions

`event_stream_listen` is enabled by default. It receives multicast on the backend, with explicit bounded duration/output and cancellation. Enabling this tool does not enable a publisher or start a socket automatically. Treat received events as external data. Preserve journal JSONL and report observed socket, parse and truncation conditions. Do not promise detection of all packet loss, complete responses, session identity or recovery of missing events.

The opt-in network tool set provides `network_list`, `prompt_listener_info`, and `prompt_send`; it is disabled by default. Listing returns registered endpoints, host locality, workspace/name, attachment, current session and usage instructions as distinct fields. Listener info returns the selected attachment's usable reply-to address, endpoint identity and an example reply tool call. It does not claim the address is bound to a saved session. Do not guess one endpoint when the caller's selection is ambiguous.

`prompt_send` sends a typed CBOR action through the workspace connection to the selected attachment. That frontend performs the TCP connection and transfer under its explicitly enabled sending capability, then returns a correlated completion/failure receipt. The backend never falls back to making the TCP connection itself. No frontend means a clear capability error. Target identity, request identity, maximum size and deadline are checked; disconnect/uncertain delivery is never automatically retried. Successful complete transmission ends with a normal disconnect. A detected failure, deadline or cancellation during transfer aborts it so a receiving listener can discard its partial draft; it must not deliberately turn that failure into a successful EOF submission. This is a network action, not an arbitrary shell command. It must not take over the terminal or block its event loop.

Reply instructions are included only when requested. They identify the originating attachment's listener and the tool invocation needed to reply, not a fixed saved session. Multiple attachments require explicit selection or the unambiguous controlling attachment. A reconnect creates a new attachment identity; old CBOR send requests must not be transferred to it automatically. No automatic fan-out, automatic context discovery, or autonomous reply loop is introduced.

## Settings and validation

Use `[ui] prompt_listener`, `proto`, and `simulate_typing_ms` for frontend settings. Use `[server] event_multicast`, `event_multicast_base`, `event_multicast_port`, `ip_multicast_if`, `ip_multicast_ttl`, and `disable_multicast_loop` for publication. Use `[agent] network_tools = false` and `disable_event_stream_listener = false` for tool capabilities. Add matching application-prefixed environment variables and CLI options. Zero typing delay means disabled. Empty listener/destination means disabled.

Verify the TCP path against raw socket senders as well as `--feed-tcp`: multiline input, every split of UTF-8 characters, incomplete/invalid input, empty input, normal EOF/half-close versus detected read errors/reset, size limits, concurrent connection rejection through paced playback, existing draft preservation, no partial queue entries, turn-queue admission, busy generation, session changes between connections and during receipt, attachment/backend switching, partial-draft cleanup/cancellation, pacing/backpressure, and frontend responsiveness. Prove the feeder bypasses broken CAI config/auth/storage and forwards arbitrary binary bytes unchanged. Inject sender errors before EOF and verify they do not submit an incomplete prompt.

Verify multicast JSONL byte equivalence, records larger than a datagram, tolerance of partial lines at late joins without requiring an identity baseline, bounded memory, send failure/nonblocking behavior, no-frontends operation, isolation of two groups on the shared port, automatic allocation races, pool exhaustion, registration cleanup/crash staleness, reconnect notices, interface/family settings, listing scopes, tool opt-in defaults, receive limits/cancellation, and correlated frontend-only sends including missing/disconnected attachments. Use ordinary Debug checks and focused musl tests with default worker stacks; rebuild and exercise the production musl binary. Keep the full release matrix deferred.
